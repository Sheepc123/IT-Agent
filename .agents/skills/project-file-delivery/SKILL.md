# 逐文件交付说明

适用于本仓库有持久化文件改动的交付答复。用户要求能逐项看清完成的代码和文件。

1. 先用一两句话说明实现结果与当前边界。
2. 逐个列出本次实际新增、修改、删除或重命名的项目文件。每个文件单独一项，使用可点击路径，说明它解决什么问题、包含哪些主要函数或入口、每个函数做什么。没有函数的配置、文档、数据和资源文件明确写“无函数”，说明其配置项或内容的作用。锁文件和变更日志也单独列出。
3. 对大型文件，列出对外入口和关键函数，不机械罗列每个私有辅助函数；如函数之间有调用关系，用一句话讲清。文件删除或重命名时说明原路径和影响。
4. 给出实际运行的检查、测试和结果；未运行的检查、模拟环境及仍未完成的事项明确写出。不要把“写了代码”说成“业务已经通过”。
5. 文件清单以本次改动为准，避免把只读查看的文件列为已修改；不得输出密钥、令牌或敏感数据内容。

项目要求每次改动记入 `scripts/CHANGELOG.md`，答复中的文件清单应与本次变更记录一致。
